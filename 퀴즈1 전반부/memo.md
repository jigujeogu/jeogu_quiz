# 스탠바이미 1 내장 브라우저 최적화 메모

## 실행 조건

- 대상 기기: LG 스탠바이미 1 `27ART10AKPL`
- 화면: FHD 1,920 × 1,080, 세로 회전 사용
- 실행 방식: 스탠바이미 내장 웹 브라우저에서 URL 접속
- 이후 여러 페이지와 하나의 콘텐츠로 통합 예정
- 이 페이지가 단독으로 수 시간 연속 실행될 가능성은 낮음

## 현재 판단

현재 페이지는 자산이 가볍고 구조가 단순해 스탠바이미용으로 충분히 개선할 수 있다. 다만 현 상태 그대로는 스탠바이미 1에서 정상 표시를 보장할 수 없다.

스탠바이미 1의 기본 플랫폼은 webOS 6.0이며, 호환성 검토 시 Chromium 79를 최저 기준으로 삼아야 한다. 현재 레이아웃이 사용하는 `aspect-ratio`, `dvh`, `dvw`는 Chromium 79에서 지원되지 않는다. 이 속성들이 무시되면 `#scene-wrapper`가 정상적인 크기를 얻지 못해 화면이 축소되거나 보이지 않을 수 있다.

## 필수 보완 사항

### 1. Chromium 79용 화면 크기 폴백 — 완료

- `100dvh`, `100dvw`보다 먼저 `100vh`, `100vw`를 선언한다.
- `aspect-ratio`에만 의존하지 않고 JavaScript에서 실제 viewport 크기를 기준으로 9:16 컨테이너의 폭과 높이를 직접 계산한다.
- `window.innerWidth`, `window.innerHeight`를 사용해 다음 원칙으로 계산한다.
  - 세로 화면에서는 높이를 우선 사용한다.
  - 계산된 폭이 viewport보다 넓으면 폭을 기준으로 다시 계산한다.
  - 최종 컨테이너는 항상 9:16 비율을 유지한다.
- 최초 진입, `resize`, 화면 회전 후 모두 다시 계산한다.
- 현재의 1080 × 1920 디자인 좌표계는 유지해도 된다.

### 2. 외부 폰트 의존 제거 — 완료

- jsDelivr의 Pretendard CSS 링크를 제거하고 `assets/font/PretendardVariable.woff2`를 `@font-face`로 연결한다.
- 행사장 Wi-Fi가 끊기거나 느려도 폰트와 배치가 동일하게 표시되어야 한다.
- 폰트 로딩 전후로 텍스트 폭이 달라지지 않는지 확인한다.

### 3. 내장 브라우저 표시 영역 대응

- 주소창이나 브라우저 UI가 표시된 상태에서도 콘텐츠가 잘리지 않아야 한다.
- `document.documentElement.clientWidth/clientHeight`와 `window.innerWidth/innerHeight` 중 실기기에서 안정적인 값을 확인한다.
- 브라우저 확대/축소 배율은 100%로 고정해 테스트한다.
- 가능하면 행사 시작 전에 브라우저의 전체 화면 또는 UI 최소화 상태를 준비한다.

### 4. 터치 입력 안정화 — 완료

- 현재 `pointerdown` 방식은 유지할 수 있다.
- 한 번의 터치가 중복 처리되지 않도록 짧은 입력 잠금 또는 장면 전환 중 잠금을 둔다.
- 빠른 연속 터치로 장면 1에서 장면 3까지 한꺼번에 넘어가지 않도록 한다.
- 장면 1은 초기 경로 등장 완료 시점까지, 장면 2는 운송수단 등장 완료 시점까지 다음 장면 전환을 차단한다.
- 장면 3은 마지막 물음표의 최초 등장이 완료되는 진입 후 `1.55초`부터 다음 페이지 전환을 허용하도록 준비한다.
- 필요하면 `touch-action: manipulation`과 텍스트 선택 방지를 페이지 컨테이너에만 적용한다.
- 화면 가장자리와 SVG 위를 눌러도 동일하게 입력되는지 확인한다.

### 5. 통합을 위한 생명주기 정리

이 페이지를 다른 페이지와 합칠 때 다음 인터페이스를 두는 것이 안전하다.

- `start()`: 초기 상태 설정, 타이핑 및 애니메이션 시작
- `reset()`: 장면 번호, 표시 클래스, 텍스트, 커서를 최초 상태로 복원
- `pause()`: 타이머와 반복 애니메이션 일시 정지
- `destroy()` 또는 `unmount()`: 이벤트 리스너와 타이머 제거

통합 화면에서 이 페이지를 단순히 숨기기만 하면 무한 CSS 애니메이션이 계속 실행될 수 있다. 페이지 이탈 시 애니메이션을 정지하거나 DOM에서 제거해야 한다.

### 6. 스타일과 DOM 이름 격리

- `html`, `body`, `*`에 적용한 스타일은 통합 프로젝트의 다른 페이지에 영향을 줄 수 있다.
- 통합 시 모든 스타일을 이 페이지 전용 루트 요소 아래로 제한한다.
- 일반적인 `.pulse-ring`, `.cursor`, `.pop`, `.is-visible`, `.is-hidden` 이름에는 페이지 전용 접두사를 붙이는 것을 권장한다.
- 현재 ID가 통합 프로젝트의 다른 페이지와 중복되지 않도록 확인한다.
- 가장 안전한 방식은 페이지 컴포넌트 단위 격리이며, 상황에 따라 `iframe`도 선택할 수 있다.

## 성능 및 안정성

- 현재 `index.html`이 실제 참조하는 SVG는 14개, 합계 약 250KB로 가볍다.
- 영상, Canvas 렌더 루프, 대형 비트맵이 없어 현재 페이지 자체의 메모리 위험은 낮다.
- 여러 개의 CSS 무한 애니메이션은 짧은 체류에는 문제가 크지 않지만 페이지 이탈 후에는 반드시 멈추는 편이 좋다.
- `filter: drop-shadow()` 애니메이션은 실기기에서 끊김이 보일 경우 그림자 강도 또는 적용 대상을 줄인다.
- 새로운 페이지가 추가되어 전체 자산이 커지면 초기 페이지에 필요한 자산만 먼저 불러오고 나머지는 순차 로딩한다.

## URL 배포 시 주의사항

- 모든 자산을 HTTPS의 동일 출처 또는 정상적인 CORS 설정 아래 제공한다.
- HTML에서 사용하는 `assets/...` 상대 경로가 배포 URL에서도 유지되는지 확인한다.
- 행사장 네트워크에 장애가 발생하면 URL 자체에 접근할 수 없으므로 현장 전용 공유기나 로컬 서버 등 별도 운영 방안을 검토한다.
- 배포 서버에서 HTML 캐시를 너무 길게 설정하면 행사 직전 수정 사항이 반영되지 않을 수 있다.
- 행사 전에는 실제 운영 URL을 즐겨찾기에 등록하고 자동 화면 꺼짐, 절전, 네트워크 재접속 동작을 확인한다.

1. ✅ Chromium 79용 viewport 및 9:16 폴백 구현 완료
2. ✅ Pretendard 폰트 로컬화 완료
3. ✅ 터치 연속 입력 방지 완료
4. 페이지 `start/reset/pause/destroy` 구조 추가

6. 통합 페이지에서 진입·이탈 반복 테스트

## 실기기 검수 체크리스트

- 세로 방향에서 화면이 9:16으로 중앙 정렬되고 잘리지 않는다.
- 첫 진입 시 검은 화면이나 순간적인 과도한 확대가 없다.
- 글꼴, 줄바꿈, 글자 굵기가 제작 환경과 동일하다.
- 주소창 표시 여부가 바뀌어도 주요 요소가 잘리지 않는다.
- 첫 터치가 타이핑 완료로 처리된다.
- 다음 터치마다 장면이 정확히 한 단계씩 전환된다.
- 빠른 연속 터치와 길게 누르기에도 중복 전환되지 않는다.
- 모든 SVG와 애니메이션이 깨지거나 심하게 끊기지 않는다.
- 가로로 돌렸다가 세로로 복귀해도 크기와 위치가 복구된다.
- 다른 페이지로 이동한 뒤 이 페이지의 애니메이션과 타이머가 남지 않는다.
- 여러 페이지를 20~30회 왕복해도 느려지거나 브라우저가 종료되지 않는다.
- Wi-Fi 재연결 및 페이지 새로고침 후 정상적으로 처음부터 시작된다.
